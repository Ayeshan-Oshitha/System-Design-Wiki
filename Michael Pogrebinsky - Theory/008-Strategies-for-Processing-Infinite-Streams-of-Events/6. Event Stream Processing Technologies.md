# Event Stream Processing Technologies

**In this lesson:** real tools that implement the window strategies from this section (tumbling, hopping, sliding, session).

1. Apache Kafka Streams
2. Apache Flink
3. Azure Stream Analytics

---

### 1. Apache Kafka Streams

> **A client library (Java and Scala) for building applications and microservices that process continuous streams of records coming through the Kafka message broker.**

- **Client library** means it runs **inside our own microservice**. No separate cluster is needed.

**It supports:**

1. **Per-record, real-time processing** (each event on its own)
2. **Stateful processing using windows** ("stateful" means it remembers earlier events, like a window's buffered events)

### 2. Apache Flink

> **A framework and distributed processing engine for building scalable streaming ETL, analytics and event-driven applications. It's designed for stateful computations over bounded and unbounded streams of events.**

- **ETL** = Extract, Transform, Load: read data, change it, and write it somewhere else.
- **Bounded** stream = has an end (like a file). **Unbounded** = never ends (like live events).

**Apache Flink can:**

1. Run as a **distributed system** whose computing resources are allocated and managed by [Hadoop YARN](https://hadoop.apache.org/docs/stable/hadoop-yarn/hadoop-yarn-site/YARN.html) or [Kubernetes](https://kubernetes.io/)
2. Run as a **standalone distributed cluster**
3. Be used as a **client library** for building microservices

**More information:**

- [Apache Flink architecture](https://nightlies.apache.org/flink/flink-docs-release-2.0/docs/concepts/flink-architecture/)
- [Windowing with Apache Flink](https://nightlies.apache.org/flink/flink-docs-master/docs/dev/datastream/operators/windows/) (Java and Python code examples)

### 3. Azure Stream Analytics

> **A real-time analytics service for processing and analyzing streaming data from various sources. It's fully managed and serverless, and uses a SQL-like query language to process data streams with windows.**

- **Fully managed / serverless:** Azure runs the servers; we only write queries.

**Window examples:**

- [Windowing overview](https://learn.microsoft.com/en-us/stream-analytics-query/windowing-azure-stream-analytics)
- [Tumbling Window](https://learn.microsoft.com/en-us/stream-analytics-query/tumbling-window-azure-stream-analytics)
- [Hopping Window](https://learn.microsoft.com/en-us/stream-analytics-query/hopping-window-azure-stream-analytics)
- [Session Window](https://learn.microsoft.com/en-us/stream-analytics-query/session-window-azure-stream-analytics)
- [Sliding Window](https://learn.microsoft.com/en-us/stream-analytics-query/sliding-window-azure-stream-analytics)

---

**Key idea:** Kafka Streams is a Java/Scala library inside your microservice for Kafka data. Flink is a distributed engine (on YARN, Kubernetes, standalone or as a library) for stateful bounded and unbounded streams. Azure Stream Analytics is a serverless cloud service queried with SQL. All three support tumbling, hopping, sliding and session windows.

---

## Short Note

- **Kafka Streams:** Java/Scala **client library** for Kafka streams; per-record + stateful windowed processing; all 4 window types.
- **Apache Flink:** distributed engine for streaming ETL, analytics, event-driven apps; stateful, bounded + unbounded streams; runs on **YARN/Kubernetes**, standalone cluster, or as a library.
- **Azure Stream Analytics:** fully managed, **serverless** cloud service; **SQL-like** queries over streams with all 4 window types.

# Popular RPC Frameworks and Technologies

This lesson lists three popular RPC frameworks. Each one gives us the parts we learned in [2. RPC - Remote Procedure Calls](2.%20RPC%20-%20Remote%20Procedure%20Calls.md): an **Interface Description Language (IDL)**, a way to generate **stubs**, and a way to send the calls.

---

### 1. gRPC

gRPC is a **modern, open-source, high-performance** RPC framework.

1. **Created by:** Google, in 2015, as the next generation of its own internal RPC system
2. **Transport protocol:** HTTP/2 (how the messages travel over the network)
3. **IDL:** Protocol Buffers
4. **Supported languages:**
   1. C#
   2. C++
   3. Dart
   4. Go
   5. Java
   6. Kotlin
   7. Node
   8. Objective-C
   9. PHP
   10. Python
   11. Ruby

### 2. Apache Thrift

Thrift is a **lightweight, language-independent** software stack for point-to-point RPC (direct calls between two programs).

1. **Created by:** Facebook, for "scalable cross-language services development"
2. **IDL:** its own, called the **Thrift interface description language**
3. **Supported languages:** more than **28**, including C++, Java, Python, Go, Scala, Swift, PHP, Ruby, Perl, C#, JavaScript and Node.js

This wide language support makes it easy for programs written in different languages to share data and call remote procedures.

### 3. Java Remote Method Invocation (RMI)

An RPC framework that lets one **Java Virtual Machine (JVM)** call methods on an object running in **another JVM**.

1. **IDL:** **Java itself**, so there is no separate description language
2. **Supported languages:** Java only (both sides must run on the JVM)

---

### Comparison

| | gRPC | Apache Thrift | Java RMI |
| --- | --- | --- | --- |
| **Created by** | Google (2015) | Facebook | Java (part of the Java platform) |
| **IDL** | Protocol Buffers | Thrift IDL | Java |
| **Languages** | 11 (C#, C++, Dart, Go, Java, Kotlin, Node, Objective-C, PHP, Python, Ruby) | 28+ | Java only |
| **Key point** | Modern and high performance, uses HTTP/2 | Lightweight, the most languages | JVM to JVM |

---

**Key idea:** gRPC (Google, HTTP/2, Protocol Buffers), Apache Thrift (Facebook, 28+ languages) and Java RMI (JVM to JVM) are popular ways to build RPC APIs. Each one has its own IDL.

---

## Short Note

- **gRPC:** Google (2015), modern, open source and high performance. **HTTP/2** transport, **Protocol Buffers** IDL, and 11 languages.
- **Apache Thrift:** Facebook, lightweight and language-independent, point-to-point RPC. Its own **Thrift IDL**, and **28+ languages**.
- **Java RMI:** one JVM calls methods on an object in another JVM. **Java is the IDL**, so it's Java only.
